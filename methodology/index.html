Methodology

From broad discovery to triplet-grounded event evidence

The Observatory separates article retrieval, classifier scoring, ontology triplet validation and event construction. Each stage leaves an auditable record rather than collapsing all uncertainty into one label.

The current release combines the existing Oil event snapshot with 401 published Ghee articles. This includes 218 model-unclear records retained for transparent review; they are not presented as settled incidents. The Ghee scope audit excluded 16 records and 66 are held for manual review rather than published as settled incidents. A separate title-only publication filter keeps 272 TTD-case sources in an audit archive while the Ghee event assembly is rerun. It also adds 196 Milk articles assembled under the same Oil/Ghee event contract, of which 92 are model-unclear review records and 68 are marked provisional because their events are not fully triplet-grounded. Milk technical-failure recovery is still in progress, so recovered Milk records will appear in a later update.

Public workflow

Eight stages in the Observatory

These stages describe what the pipeline does. They are not a project progress tracker.

01

Article collection

Candidate news records are discovered through approved search queries and source collections. Retrieval failures and duplicate text are audited instead of being interpreted as negative evidence.
02

Text cleaning

Publisher boilerplate and malformed text are conservatively cleaned. Each retained article is split into bounded chunks while preserving the article and chunk identifiers needed to trace every later claim.
03

Relevance classification

A food-specific classifier scores whether an article is likely to contain useful safety evidence. The score is a retrieval aid, not the final event decision.
04

Large-model event validation

Qwen evaluates the full article together with retained triplet evidence and assigns relevant_event, irrelevant, or unclear. Claim status remains a separate field. Mistral is used only when Qwen has a technical failure.
05

Entity extraction

The event object retains food items, adulterants, issue types, place, date, quantities, authorities, actions, laboratory context, evidence quotations and other reported entities.
06

Ontology mapping

Article claims are represented as subject-predicate-object triplets using FFLO and provenance vocabulary. Accepted, schema-gap and unresolved outputs remain distinguishable.
07

FSSAI comparison

Extracted news issues can be compared with the parameters and scope of official surveys only after units, geography, period and evidence type are made compatible.
08

Interactive repository

The website exposes source text, classifier metadata, model decisions, event fields, exact evidence and triplet audit trails so each published record can be inspected.

Triplet-first validation

How ontology claims become event fields

The production architecture retains the useful structure of the shared Food-Safety-KG pipeline while adding correction, cross-model validation and exact-evidence safeguards.

A

Qwen candidate extraction

Every cleaned chunk is sent through the FFLO extraction prompt. A candidate contains subject, subject type, predicate, object, object type, confidence, an evidence span and its source identifiers.
B

Deterministic schema routing

Code checks whether entity types and predicates exist and whether each predicate permits the proposed subject and object types. Candidates are routed as schema-valid, schema-invalid, schema-mismatch, or zero-triplet chunks.
C

Qwen semantic judgment

A separate model call compares each candidate with its article excerpt. It tests entailment, direction, relation choice, entity types and whether a zero-triplet chunk missed a relation.
D

Atomic correction and recheck

Repairable claims are rewritten one at a time. Corrected triplets must pass the FFLO structure check, exact contiguous evidence checks and a second semantic judgment before they can be accepted.
E

Mistral triplet validation

Mistral independently assesses Qwen's accepted, corrected, schema-gap and unresolved candidates. Unsupported claims are rejected; low-confidence or invalid evidence responses remain unresolved rather than being silently promoted.
F

Qwen event assembly

The full article, accepted triplets, schema-gap claims and unresolved context are assembled into a rich event object. Unresolved triplets may provide context but are not treated as settled ontology facts.
G

Deterministic event checks

Code records event-schema, exact-evidence and cited-triplet-grounding checks. These checks remain visible as diagnostics; they do not replace the model relevance label in this release.
H

Technical fallback and publication

Qwen semantic outputs are retained as-is. Only Qwen technical failures are sent to Mistral. Strictly recovered records are validated; parseable relevant events that fail citation grounding are published as provisional, with unresolved evidence visible. A record with no model output is excluded.

Evaluation concepts

Precision, recall, soundness and completeness

Precision

Among articles predicted relevant by the classifier, the proportion that meet the reference relevance criteria.

Recall

Among reference-relevant articles, the proportion recovered by the classifier.

Soundness

Whether an extracted claim is supported by the article, structurally valid and mapped with the correct direction and entity types.

Completeness

Whether the pipeline retrieves and represents all in-scope evidence. Neither web discovery nor model extraction guarantees completeness.

Why the model stack changed

An early local SciPhi/Triplex test used five oil articles split into ten chunks. The compact prompt produced no usable triplets, while the full FFLO prompt exceeded a 6 GB laptop GPU. The production experiments therefore moved to Qwen and Mistral on larger GPUs while retaining FFLO-style outputs and deterministic validation.

Interpretation note

News reports are source claims, not independent laboratory verification. A `relevant_event` label means the model identified a concrete in-scope food event; the separate claim status records whether that event is suspected, alleged, pending, authority-reported, or laboratory-confirmed. Unresolved triplets are displayed for transparency and are not equivalent to accepted ontology facts.
